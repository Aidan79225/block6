# 產品核心（Product Core）

> 這份文件定義 BLOCK6 Time Manager 要做什麼、不做什麼，以及判斷的依據。
> 新功能提案、既有功能的去留，都以這份為準。與這份牴觸的設計，改設計不改這份；
> 真的要改這份，先在 PR 裡說明理由。

---

## 一、一句話

> **用最少的規劃決策，管理最多的時間，而且事後不後悔。**

三個部分都不能少：

- **最少的規劃決策** — 這是目標函數
- **最多的時間** — 這是分母
- **事後不後悔** — 這是約束條件，防止「不做任何決定」這個退化解

---

## 二、核心指標：規劃比值

```
規劃比值 = 被管理的小時數 ÷ 規劃決策數
```

一週約 84 小時醒著的時間（6 格 × 2 小時 × 7 天）。「規劃決策」= 使用者在**規劃階段**必須做出的每一個選擇（選類型、打標題、選歸屬…）。執行階段的操作（打勾、寫日記）不計入，那是另一條軸。

| | 每格的規劃決定 | 全週決策數 | 比值 |
| --- | --- | --- | --- |
| 純方法（書上的 BLOCK6） | 類型 + 標題 = 2 | ~84 | **1 小時 / 決策** |
| 2026-08 的實作 | 類型、標題、描述、歸屬 KR、歸屬 Project、子任務 = 6 | 250+ | 0.33 小時 / 決策 |
| 目標（節奏優先） | 只決定「這週有什麼不一樣」 | ~20 | **4+ 小時 / 決策** |

（概算，不是精算。重點是量級，不是小數點。）

**這個表就是這個專案最重要的一張表。** 到 2026-08 為止，實作比它所實作的方法**還差三倍**，距離該有的樣子差 12 倍。每一個新功能都在讓比值變差。

### 怎麼用它

估算一個功能對比值的影響。分母增加而分子沒動的功能，預設不做。

- 「歸屬 KR」+「歸屬 Project」= 每週 +84 個決策，換來 0 小時的管理範圍 → 砍
- 「預設節奏範本」= 一次砍掉 42 個類型決策 → 做
- 「常駐節奏」= 每週砍掉 60+ 個決策 → 最高優先

## 三、為什麼粗顆粒度就是產品本身

為什麼是一天 6 格，而不是 96 個 15 分鐘欄位？因為 6 個決定很便宜。

日曆逼你決定每件事的起訖時間，那很貴。**粗顆粒度不是簡化後的妥協，它是這個產品唯一的護城河。**

| | 規劃成本 | 管理時間 |
| --- | --- | --- |
| Google Calendar | 每個事件要決定起訖時間 | 管「約定」，不管時間分配 |
| Notion / Obsidian | 無限層級，成本無上限 | 什麼都能管，所以什麼都沒管 |
| Todoist | 低 | 管事項，不管時間 |
| **BLOCK6** | **一格一個決定** | **一格 2 小時** |

**只有我們在賣粗顆粒度。** 任何把顆粒度往下拉的功能（子任務把 2 小時拉到「一件小事」，計時器把它拉到秒）都在磨掉這個優勢，必須有很強的理由才能留。

## 四、迴圈

```
① 分配 ──────────────► ② 執行
   42 格，稀缺，選擇      這格發生了什麼
   ▲                        │
   │                        ▼
④ 回顧 ◄────────────── ③ 感受
   什麼不值得              一天結束的一句話
```

**每個功能都要能說清楚它服務 ①②③④ 哪一步。如果要講超過一句話，它就不該在主要流程裡。**

四步是同一個迴圈，不是四個分頁。特別是 ④ → ① 那條線：回顧的產出必須直接變成下週規劃的輸入，否則回顧只是一份沒人看的報表。

---

## 五、「有效」的定義：不是完成率

完成率是很差的有效性代理：

- 完成率高，可能只代表計畫得太保守
- 完成率低，可能是被一件**更重要**的事拉走了 —— 那是好事，不是失敗

**有效 = 事後回看，不覺得那 84 小時被浪費了。**

所以週回顧該問的不是「你完成幾 %」，而是：

> **「哪幾格你事後覺得不值得？」**

這個問法有兩個好處：

1. 它才是真正的有效性訊號
2. **它的答案是零成本的下週輸入** —— 刪除比新增便宜一個數量級。「這格下週拿掉」遠比「下週我要做什麼」省力

由此推出這個產品該有的性質：**用得越久，規劃成本越低。** 節奏越校準，每週要做的決定越少。任何讓「用得越久、要維護的東西越多」的設計（累積的 OKR、專案、清單）都與核心相反。

## 六、架構決策：節奏優先（Rhythm-first）

**前提：** 使用者一週 42 格裡，30 格以上每週幾乎不變（上班、睡眠、通勤、固定運動）。

**因此：節奏是預設，本週是例外。** 不是反過來。

### 資料模型

```
rhythm_slots          背景節奏：每位使用者最多 42 列，很少變動
  (user_id, day_of_week, slot, block_type, title, direction_id, active)

blocks                本週的例外 + 執行狀態
  只在以下情況才存在一列：
    - 使用者覆寫了這週這一格，或
    - 這一格有執行紀錄（狀態、計時、子任務）
```

### 讀取規則

渲染某一週 = 對 42 個 `(day, slot)` 逐一取：

1. 該週的 `blocks` 覆寫（若存在）
2. 否則投影 `rhythm_slots`
3. 否則空格

### 這帶來的性質

- **規劃全新的一週 = 0 次寫入。** 打開就已經是完整的一週
- 使用者只編輯前景（這週有什麼不一樣），背景自動存在
- 「從上週複製」可以退場 —— 它是這個想法的弱版本，把常駐和一次性混在一起複製，還要逐格檢查

### 節奏怎麼建立（不要讓它變成新的規劃成本）

不要用一個 42 格的設定畫面來要求使用者一次填完，那只是把成本前移。

- 用現有的預設節奏範本（`buildWeekTemplate`）當初始值
- 幾週之後**自動偵測**：同一格連續 N 週是同樣的標題 + 類型 → 提示「這 32 格每週都一樣，設成常駐節奏？」
- 一鍵「把這週設為我的節奏」

### 遷移

現有的 `blocks` 資料原地保留，全部視為覆寫（行為不變）。`rhythm_slots` 是新增的一層，可以空著上線。

## 七、取捨紀錄

### 保留（核心）

| 功能 | 服務哪一步 | 說明 |
| --- | --- | --- |
| 42 格週網格 | ① | 稀缺感是方法的力量來源 |
| 四種類型（核心/休息/緩衝/一般） | ① | 方法真正的洞見：逼你承認休息與緩衝不是可選的 |
| 常駐節奏 | ① | 最高槓桿，**尚未實作** |
| 格子上一鍵回填狀態 | ② | 已於 `a04efc4` 實作 |
| 日記 | ③ | 迴圈的燃料，目前被當成配件對待（藏在側欄底部、要先選一個 block、漏一天永久鎖死） |
| 週回顧 | ④ | 目前是唯讀報表，需要改成以「哪幾格不值得」結尾並回饋到 ① |

### 降級

| 功能 | 理由 |
| --- | --- |
| 計時器 | 測秒，但方法的單位是「一格 ≈ 2 小時」。唯一有價值的時刻是讓你發現「我以為這是一格，它吃掉三格」—— 那是 ④ 的素材。應從側欄常駐元件降級為回顧頁的一項觀察 |
| 子任務 | 唯一把顆粒度往下拉的功能。留著，但**只在執行階段出現，不進規劃流程** |
| 描述欄位 | 幾乎不影響有效性，不該預設展開 |

### 移除

| 功能 | 決定 | 理由 |
| --- | --- | --- |
| OKR（cycle / objective / key_result / progress） | **移除** | 心跳頻率差 13 倍（週 vs 季），一季才動一次的東西放在每週節奏裡永遠是冷的；`currentValue` 要手動維護，會停在最後一次有熱情的那天；`targetValue > 0` + `current/target` 的模型把**方向改變定義成失敗**，但個人的長期方向本來就會變。成本：每週 +42 個決策，收益：連週回顧頁都沒出現 |
| Projects / project_steps | **移除** | 第三套平行階層。與 OKR 同樣的問題：成本付在首頁側欄，收益在一個不在每週路徑上的分頁 |
| 週任務清單（weekly_tasks） | **待決** | 「每週重複做的事」本來就該是常駐節奏的格子。它現在是平行清單：不影響完成率、不進回顧、不佔任何一格，讓「一週只有 42 格」這個承諾破功。節奏功能上線後應該併入 |
| 「從上週複製」 | 節奏上線後退場 | 見第六節 |

### 長期方向要怎麼做（取代 OKR）

需求是真的 —— BLOCK6 規劃了日與週，缺一個長期方向。但解法不是宣告目標，而是**顯示軌跡**：

1. **方向 = 三行字**，沒有數值、沒有截止日，隨時可改，改了不算失敗
2. **方向綁在常駐節奏上，不綁在單一格子上** —— 設定節奏時標一次，之後每週自動繼承。**規劃成本為零**
   （早期草案是「每格選一個方向」，那每週增加 42 個決策，違反核心，已否決）
3. **累積視圖** = 橫軸是週、縱軸是格數的堆疊圖。看到某個方向從 12 格掉到 2 格，不需要任何人告訴你偏離了。「未標」那一欄同樣有力
4. **一年只有 52 週** — 把 42 格的稀缺感往上放一層。同一個視覺語言、同一個概念，而且不需要任何輸入

前瞻性的推力放在 ④ → ① 的接縫，不放在獨立的季度儀式：

> 回顧頁最後一行：「下週想把哪個方向的格數拉回來？」→ 選一個 → 直接進入下週規劃，該方向已預選

## 八、新功能的門檻

提案前先回答這三題，答不出來就不做：

1. **它服務 ①分配 / ②執行 / ③感受 / ④回顧 哪一步？** 要講超過一句話就不該在主要流程裡
2. **它讓規劃比值變好還是變差？** 分母增加而分子沒動的，預設不做
3. **它把顆粒度往下拉嗎？** 如果是，它必須只出現在執行階段

---

## 九、待辦（按比值排序，不按開發難度排序）

1. **常駐節奏** — 資料模型分離背景節奏與本週例外（第六節）
2. **區間框選命名** — 一個手勢命名一整列/一整塊，一個決定管 10 小時。純 UI，不動資料模型
3. **回顧頁改問「哪幾格不值得」** — 把回顧變成零成本的下週輸入
4. **移除 OKR 與 Projects** — 四張表變零，側欄少兩個下拉
5. **長期方向：三行字 + 累積視圖 + 52 週**
6. PWA manifest + 提醒 — 提醒的內容是「這週有什麼不一樣嗎？」，不是「來規劃」
7. 放寬日記補寫窗（至少允許補當週）；日記給一個不需要先選 block 的入口
